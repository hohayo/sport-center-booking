# 運動中心預約外掛（Chrome 擴充程式）v0.1

作者：Kyle, Chuang

```
extension/        Chrome 擴充程式本體（載入這個資料夾）
license-server/   授權伺服器（Supabase 邊緣函式 + 資料表 + 金鑰工具）
```

## 一、現在就能測試（不需要伺服器）

1. 解壓縮這個 zip。
2. Chrome 網址列輸入 `chrome://extensions`，右上角打開「開發人員模式」。
3. 按「載入未封裝項目」，選 **extension** 資料夾。
4. 點瀏覽器右上角的擴充功能圖示（拼圖 → 運動中心預約外掛），會開啟授權設定頁。
5. 輸入測試碼 `DEV-TEST-0000`，按「啟用」，看到「✔ 已啟用（測試模式）」。
6. 登入運動中心網站，開啟預約頁，右下角會出現面板，最上方顯示授權狀態。
7. 如果之前裝過 Tampermonkey 版腳本，請先停用，以免出現兩個面板。

沒有啟用授權時，按「執行」會被擋下並自動開啟設定頁。

## 二、正式上線前檢查（發給別人之前一定要做）

1. **建立金鑰**：在 `license-server` 資料夾執行 `node tools/gen-keys.mjs`。
   - 公鑰貼到 `extension/config.js` 的 `PUBLIC_KEY_JWK`。
   - 私鑰在 `keys/private.jwk.json`，只放在伺服器的 secret，**不要放進 extension 資料夾、不要上傳 GitHub**。
2. **建立資料表**：把 `schema.sql` 貼到 Supabase 的 SQL Editor 執行。
3. **部署邊緣函式**：
   ```
   supabase secrets set LICENSE_PRIVATE_JWK='（gen-keys.mjs 印出的那串）'
   supabase functions deploy license --no-verify-jwt
   ```
   把函式網址（`https://<專案>.supabase.co/functions/v1/license`）填到 `config.js` 的 `API_URL`。
4. **關掉測試模式**：`config.js` 裡 `DEV_MODE` 改成 `false`。**這步沒做，任何人輸入 DEV-TEST-0000 都能使用。**
5. **發授權碼**：照 `schema.sql` 裡的範例 SQL 新增，授權碼請用夠長的隨機字串（範例用 32 碼），避免被猜中。
6. **跑一次驗證測試**：`node license-server/tools/test-license.mjs`，應該全部 PASS。

## 三、授權機制說明

- 啟用時，擴充程式把「授權碼 + 隨機裝置 ID」送到伺服器；伺服器檢查授權碼是否存在、是否停用、是否過期、裝置數是否超過上限，通過就回傳一張**用私鑰簽章的憑證**（有效 7 天）。
- 擴充程式內只有**公鑰**，用來驗證憑證有沒有被竄改、有沒有過期、是不是這台裝置的。
- 憑證剩不到 2 天時，會在背景自動續期；停用授權碼後，最慢 7 天內該裝置就會失效。
- 換電腦：在資料庫刪除該授權碼的 activations 紀錄（見 `schema.sql`）。

**限制**：這是在使用者電腦上執行的程式，懂程式的人可以把檢查那幾行刪掉，所以這個機制只能擋一般使用者，不能擋住有心人。

## 四、上架 Chrome 線上應用程式商店

- 需要開發人員帳號（一次性註冊費 5 美元）。
- 上傳前把 `extension` 資料夾壓成 zip（資料夾內容放在 zip 根目錄，不要多包一層）。
- 填寫商店說明、截圖、**隱私權政策**（要說明會連到授權伺服器、會儲存裝置 ID 與授權碼）。
- 商店不接受混淆過的程式碼；本專案程式碼可讀，可直接上傳。
- 可選「不公開」，只有拿到連結的人能安裝。

## 五、已知限制（尚未在實際網站驗證）

- 瀏覽器端的面板與點擊流程沿用 Tampermonkey 版（v0.4）；「預定場地」按鈕在新生網站上能否被腳本成功觸發，需要你實測。
- 其他五個運動中心的頁面結構我沒有看過，場地清單與按鈕可能需要調整。
- 使用條款與法律風險請自行評估，建議先向運動中心確認。
